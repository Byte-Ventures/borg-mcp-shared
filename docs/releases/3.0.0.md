This major release introduces protocol 15 and the shared contract for recovering
failed attachment finalization. It adds an internal, domain-separated SHA-256
receipt derived from the original session bearer, strict parent-authenticated
reconciliation requests and action-bound responses, and distinct finalized and
retired operation errors. The receipt is not a credential and cannot restore a
lost bearer. Existing ordinary attach requests and responses remain unchanged;
exact-bearer retries preserve the original drone, session, and initial log cursor.

Portable conformance now covers pending-only retirement, parent-scoped cancellation
tombstones, finalization, current authorization and terminal refusals, concurrent
retries, and preservation of replacement sessions. Adapter implementations must
provide the new `reconcileAttachment` operation. Reconciliation response decoders
require the requested action. These are breaking protocol and adapter API changes:
protocol 15 peers reject protocol 14 rather than negotiate or decode both.

The shared contract is released first. The matching server and client recovery
implementations have not yet been published. Consumers must adopt this exact
shared registry artifact in coordinated protocol 15 server and client releases;
install the matching server before the matching client. Installing this package
alone does not provide a recovery command or complete the recovery journey.

Verification covers the shared contract and reference adapter, including negative
controls for terminal/tuple bypasses and mutation on refusal. Packed-artifact tests
verify the public package and execute its root, protocol, and conformance exports
from an installed tarball on the supported Node.js runtimes. These checks do not
establish production server transactions, persistent crash recovery, or the
printed recovery command against published consumer packages; those remain part
of the coordinated consumer implementation and release verification.
