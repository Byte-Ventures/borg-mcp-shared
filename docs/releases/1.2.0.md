This release strengthens portable naming and repository-association conformance
without changing the protocol envelope or any wire shape.

## Conformance

- Cube names must be unique per owner under ASCII case-insensitive comparison.
  Different owners may still create cubes with the same display name.
- Role names must be unique per cube under ASCII case-insensitive comparison.
  New role names accept only letters, digits, spaces, periods, underscores, and
  hyphens, must start with a letter or digit, and remain limited to 64 bytes.
- One cube may be explicitly associated with more than one repository, and each
  successful association must be observable through repository resolution.
- The README documents the suite's per-credential request volume and minimum
  request budget for each reset epoch.

## Compatibility

`PROTOCOL_VERSION` remains `13` because this release changes refusal behavior
for invalid input and corrects conformance expectations without changing a wire
shape. Matching client and server releases adopt this contract together.
